# Pull requests e manutenção dos guias

Consulte ao preparar descrições de PRs ou alterações na documentação de contribuição.

## Fluxo Git

Para branches, mensagens de commit, preparação de alterações e integração, consulte [Convenções Git](git-conventions.md) apenas quando essas operações fizerem parte da tarefa.

## Pull requests

Descreva o problema concreto e o comportamento resultante. Inclua:

- Um resumo conciso e o escopo.
- Links para issues relevantes, quando disponíveis.
- Comandos de validação e resultados, incluindo verificações que não puderam ser executadas.
- Capturas de tela para alterações visuais.
- Atualizações de configuração ou arquitetura quando afetadas.

Explique limitações relevantes sem copiar a conversa de desenvolvimento para a descrição.

## Manutenção da leitura sob demanda

[AGENTS.md](../AGENTS.md) é o ponto de entrada. Mantenha procedimentos detalhados nos guias por assunto, com indicações explícitas de quando consultá-los.

Adicione um guia apenas quando uma tarefa distinta e recorrente precisar de instruções próprias. Inclua um link no arquivo principal; não incorpore o guia nele nem exija a leitura de todos os guias para cada tarefa.

Mantenha detalhes de configuração nos arquivos de origem e referencie-os por links. Evite repetir políticas entre guias. Remova instruções desatualizadas quando a implementação mudar e verifique links relativos após mover arquivos.

Registros de tarefas, descobertas temporárias e saídas extensas de comandos não devem integrar as orientações permanentes de contribuição.
